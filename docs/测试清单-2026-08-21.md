## 本轮批量测试发现并修复的问题

1. **（致命，已修）LLM 相对日期解析错误**：上一轮修复后仅 12 条验证；本轮 46 条真实口语化复测确认日期精度很高（明日/下周X/月底/下周五等几乎全命中）。
2. **（已修）空/无意义输入会创建空标题任务**：LLM 对空白或"哦对对对"返回空标题，直接创建了空标题任务。已在 `NlpService` 加空标题守卫：空标题→回退本地用原文兜底，可在确认框丢弃。回归测试已补。
3. **（已修）本地兜底解析器 5 缺口**（无 LLM key 时走的路径）：
   - 只有时刻没有日期（如"下午5点半开会"）→ due 丢失 → 现在默认今天
   - 重复任务 + 时刻（如"每天晚上9点"）→ **时刻彻底丢失** → 现在写入 `BYHOUR/BYMINUTE`
   - "每周六日 / 每周一三五" 多天 → 只留一天 → 现在生成 `BYDAY=SA,SU`
   - "月底 / 月末" → 不识别 → 现在解析为当月最后一天
   - "明早 / 明晚 / 今晚" → 不识别还留在标题 → 现在归一化并剥离
4. **（已修）偶发 LLM 回退**：给 `enhance()` 加自动重试——超时/网络/5xx/429/网关HTML 重试一次；401/403/404 等配置性错误立即报错（不无谓等待）。重跑后原 A1.06/A4.08/A6.01 三次瞬态回退**全部走通 LLM**。
5. **（已修）隐含默认期限**：提示词补充"这个月→当月最后一天 / 睡前→今晚23:00 / 下班后→当天18:00 / 周末→最近周末；纯琐事才给 null"。重跑后 A6.03=08-21 23:00、A6.06=08-31 命中。
6. **（已修）非标准 RRULE 别名**：模型偶发输出 `FREQ=BIWEEKLY`（非 RFC 标准，`rrule` 库解析会失败→重复任务提醒静默失效），已统一归一化为 `FREQ=WEEKLY;INTERVAL=2`（`BIMONTHLY→MONTHLY;INTERVAL=2`）。

## 补充：提醒提取专项（2026-08-21 第三轮，随 v0.4.9）

> 用户反馈："LLM 对是否需要提醒/重复的提取不行"。核查发现确认弹窗的"提醒"行之前只是按"是否有日期"硬推，且**快速录入从未真正创建提醒**。本轮补全端到端。

- **实现**：本地 zh_parser + LLM 提示词均新增 `reminderMinutes`（到期前N分钟）提取；快速录入在确认后真实创建 Reminder；确认弹窗显示真实提醒；未显式提提醒且开了全局默认提醒时套用默认提前量（显式优先）；Android 上创建提醒时请求通知权限。
- **本地解析**：提前N分钟/小时/天/半小时→换算；只说"提醒/提醒我"→默认15分钟；未提→null（`test/reminder_extraction_test.dart` 5 项）。
