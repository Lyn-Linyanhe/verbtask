# VerbTask 后续路线图

## 当前版本：v0.4.12 平台验证与发布门禁

目标是让个人用户可以稳定完成“记下 → 设置提醒 → 到点查看 → 完成记录”。VerbTask 的定位是轻量的提醒记事工具，而不是番茄钟、自习室或专注学习产品。本阶段保留 JSON 本地存储和现有 Flutter 架构，优先补齐清单、完整任务编辑、系统视图、搜索筛选、提醒语义、LLM 接入和双语。

UI 基线来自竞品复核，也是本阶段待完成的验收目标：收件箱承接快速收集，今天承接执行，计划承接时间规划；移动端用低密度单列任务行，复杂字段进入详情页；看板是状态切换视图，不改变任务模型。实现后 v0.2 默认进入收件箱，以免没有截止日期的新任务在录入后消失。

## v0.3 可靠本地同步

目标是让 Android 与 Windows 在同一局域网内安全、增量、可恢复地同步。范围包括配对密钥、认证、同步游标、唯一 changeId、幂等去重、清单同步、删除墓碑、前台/托盘/周期触发，以及重复任务实例状态。

## v0.4 发布与扩展

目标是让别人能够稳定安装和迁移数据。范围包括 JSON/CSV 导入导出、系统文件选择器、原子写和恢复工具、MIT LICENSE、Android APK/Windows 安装包脚本、发布说明，以及是否增加用户自选 WebDAV/CalDAV 后端的评估。

## 明确不做

- 不做番茄钟/专注计时、自习室、习惯打卡、积分、专注统计和团队协作，不把 VerbTask 扩展成综合效率平台。
- 不在 v0.2 为了追随旧文档强行迁移 SQLite。
- 不把当前未经认证的 LAN HTTP 同步描述为安全或完成状态。

## 执行与审查门槛

- 每个功能阶段先补失败测试，再实现最小行为；服务层、NLP、RRULE、同步和提醒分别保留可独立验证的测试。
- 每个阶段完成后运行 `flutter analyze` 与对应测试；v0.2 结束前必须通过完整测试、Android debug 构建、Windows 构建和 `git diff --check`。
- UI 验收关注真实工作流而非截图：快速录入确认、搜索不触发 NLP、清单删除不产生悬空任务、看板三列状态迁移、设置中英切换和主题切换。
- 当前工作区已有本地化与主题未提交改动，后续实现必须在其上增量修改，不回滚用户或此前代理已经完成的改动。

## v0.4.11 已完成的验收项

- 本地存储损坏时保留原文件并生成恢复副本，未来 schema 版本拒绝加载，JSON 导入原子提交。
- 同步服务强制令牌鉴权，客户端/服务端统一任务 LWW；同步游标在成功应用并推送后持久化。
- 回收站删除与彻底删除分离；清单和彻底删除都使用墓碑避免旧端复活。
- 通知使用稳定任务 payload；任务提醒策略区分继承、开启和明确关闭。
- 窄屏 320/360dp、大字号 1.0/1.3/2.0 widget 测试和发布一致性检查已纳入门禁。

## v0.4.12 已完成的验收项

- Windows Release、Inno Setup 安装器和 D 盘干净安装已完成验证。
- Android release APK 已在模拟器冷启动、通知授权和精确闹钟权限时机上完成验证。
- 产品定位、竞品边界和 UX 审核结果已归档；VerbTask 保持提醒 + 记事定位。

正式 Android 发布签名、多设备真实局域网同步和多屏 DPI 仍需在正式发布环境中完成最终验收。
