## 1. 项目概述

一款**个人自用、开源（MIT）**的任务管理 App。
- 平台：**Android**（手机优先）+ **Windows**（桌面）
- 数据：**无账号、纯本地、私有**
- 开源：发布到 GitHub，别人可自行下载 **APK + Windows 安装包**使用

---

## 2. 需求（定稿）

### 2.1 定位与非功能
| 项 | 决定 |
|---|---|
| 归属 | 个人自用 + 开源分发 |
| 账号 | 无账号，纯本地 |
| 数据 | 本地存储、私有 |
| 平台 | Android（手机优先）+ Windows |
| 语言 | 中英双语，一键自由切换 |
| 开源协议 | MIT |

### 2.2 功能需求
**任务基础**：新建 / 编辑 / 完成 / 未完成 / 删除 / 备注字段。

**分类组织**：收件箱（Inbox）随手记录 + 清单（Lists）归类。（不做文件夹 / 标签）

**任务字段**：
- 标题、备注
- 截止日期：支持「仅日期」与「日期+时刻」两种
- 状态/进度：未开始 → 进行中 → 完成（看板列式）
- 优先级：弱化档位；重点提供「按截止时间排序」
- 周期性：RRULE 标准（每天/周/月/每工作日 + 自定义间隔 + 每月第 N 天等）；编辑支持「只改这一次 / 这一次及以后 / 整个系列」

**提醒**：到期提醒 + 提前提醒 + 重复任务提醒；每条可单独设提前量 + 全局默认提前量；单条可关闭提醒；到期精确到时间点。

**查看**：搜索 / 排序（按截止时间等）/ 筛选；「按截止时间排序」可作为默认视图之一。

**数据安全**：回收站（删除可恢复）+ 撤销；备份 / 导出 / 导入（JSON/CSV 到本地文件）。

**自然语言录入（三级）**：
1. 内置离线规则解析（**先支持中文**），不联网
2. 可选 LLM 增强（用户自填 OpenAI 兼容接口 base_url+key，key 存本地；**默认关闭**，开启时提示任务文本会发送到该服务）
3. 永远保留手动输入（无 key 也能用）
4. 解析结果**必经弹窗确认**后才写入

**同步（纯本地/局域网）**：
- Windows 后台监听手机，**监听频率可设置**（默认不要太短）
- 提供**手动快速同步**按钮（不等监听频率、立即同步）
- 冲突处理：**Last-write-wins**（同一任务，以最后修改的整体覆盖）
- 首次配对：局域网自动发现 + 扫码兜底
- 删除同步：手机删除会同步到 Windows
- Windows 端：系统托盘 + 开机自启，默认开、可关

**后台/通知（Android 工程约束）**：
- 本地通知定时提醒（App 关闭也能弹）
- WorkManager 后台同步 + 权限引导（忽略电池优化、通知权限、精确闹钟）

## 3. 技术栈选型

| 层 | 选型 | 依据 |
|---|---|---|
| 跨端 UI/逻辑 | **Flutter** | 一套代码出 Android + Windows；AppFlowy 同类项目已验证 |
| 本地存储 | **JSON 文件（v0.2）** | 零依赖、便于 Android/Windows 纯本地分发；SQLite/Drift 留作后续评估 |
| 状态管理 | Flutter StatefulWidget + Controller（当前实现） | 与现有原型保持一致，避免本阶段引入新框架 |
| 本地通知 | `flutter_local_notifications` | Android 本地定时通知，App 关闭可弹 |
| Windows 后台/托盘 | `tray_manager` + `window_manager` | 最小化到托盘、后台监听 |
| 局域网发现 | mDNS 服务发现（`multicast_dns` / `bonsoir`） | 手机自动发现 Windows 主机 |
| 后台同步（Android） | WorkManager 定时任务 | 在闲时/连接 Wi‑Fi 时同步 |
| 离线 NLP 解析 | 中文规则解析器（自定义 + 字典/正则），可选：chrono 思路移植 | 先支持中文，离线 |
| LLM 增强 | 开放 OpenAI 兼容 HTTP 接口，用户自填 base_url/key | 可插拔 |

> 说明：v0.2 Windows 端与 Android 共用 Flutter + JSON 文件仓库；后台监听走桌面常驻（托盘）而非系统服务。SQLite/Drift 仍是未来数据量和查询需求增长后的评估方向，不属于 v0.2 实现基线。

## 4. 总体架构

```
Flutter UI (Android / Windows)
        │
        ▼
   状态层 (StatefulWidget + Controller)
        │
        ▼
 ┌─────── 业务层 ──────────────┐
 │ 任务/清单/收件箱/回收站 CRUD │
 │ 周期性调度 (RRULE)           │
 │ 提醒调度                     │
 │ 自然语言解析（离线/LLM）      │
 └──────────────┬──────────────┘
        │
        ▼
   本地存储 (JSON 文件)
        │
        ▼
   同步引擎（纯本地/局域网）
   ├─ 局域网发现 (mDNS)
   ├─ 配对（自动发现/扫码）
   ├─ 传输（本地方言/或 WebDAV 语义 over LAN）
   └─ 冲突合并（Last-write-wins + 字段时间戳）
```

## 5. 数据模型（草案）

```
Task
  id             : UUID
  title          : string
  notes          : string (备注)
  listId         : UUID? (null = 收件箱)
  status         : todo | doing | done
  due            : { dateOnly: bool, value: DateTime }  // 仅日期 或 日期+时刻
  priority       : int (弱化，预留)
  sortOrder      : double (手动排序)
  rrule          : string? (RRULE；空=非重复)
  reminders      : Reminder[]  // 每条各自提前量；可为空=不提醒
  createdAt / updatedAt : DateTime (用于 last-write-wins)
  deletedAt      : DateTime? (回收站；非空=已删除待清理)
  seriesId       : UUID? (重复任务系列标识)

Reminder
  id         : UUID
  taskId     : UUID
  offsetMin  : int (负数=到期前 N 分钟) | 绝对值时刻
  mode       : relative | absolute

List
  id, name, icon?, color?, sortOrder
```

## 6. 同步设计（纯本地 / 局域网）

### 6.1 拓扑
- 一台 **Windows 常驻后台**作为「家庭同步节点」（托盘 + 可选开机自启）。
- Android 手机是移动端，回家连同一 Wi‑Fi 时与 Windows 双向同步。

### 6.2 流程
1. **发现**：双方在同一局域网，mDNS 广播服务；手机打开 App / 回到前台时触发发现与同步。
2. **配对**：首次自动发现后，用户扫码（二维码含配对码/密钥）确认，建立信任关系。
3. **同步触发**：
   - 自动：达到用户设置的**监听/同步频率**时；或手机端回到前台、连上家庭 Wi‑Fi 时。
   - 手动：「快速同步」按钮立即执行。
4. **传输**：增量推送（按 `updatedAt` 增量），双向合并。

### 6.3 冲突处理
- 按任务级 **Last-write-wins**：比较 `updatedAt`，后改的整体覆盖先改的。
- 「删除」也当一次修改：删除方 `updatedAt` 较新则另一侧把任务移入回收站。
- 说明：任务级 LWW 实现简单、可预期（用户已确认）。若未来要字段级合并，再引入 CRDT（如 AppFlowy 的 Yrs / Automerge）。

### 6.4 说明与边界
- 手机在外的改动**不会实时**到 Windows，回家同步后才到（用户已确认可接受）。
- 离线数据以各自本地 JSON 文件为准；同步不依赖任何外部服务器。v0.2 先完成本地工作流，可靠 LAN 增量同步进入 v0.3。

## 7. 通知设计

- 提醒由**本地通知**承载：在提醒时刻由系统触发，App 关闭也能弹。
- Android：用 `flutter_local_notifications`（`zonedSchedule`，配合时区库）；Android 13+ 申请通知权限，精确到分钟的提醒需 `USE_EXACT_ALARM`。
- 全局默认提前量 + 每条任务可覆盖；单条可关闭。
- 重复任务：每个实例各自评估提醒（基于 RRULE 展开）。

---

## 8. 自然语言输入设计

- 输入框支持直接输文本；本地规则解析器**先支持中文**（`下周三下午3点交报告`、`明天`、`每天上午9点锻炼` 等），提取 任务正文 / 截止日期 / 重复 / 优先级。
- 解析结果低置信度 / 命中规则时，**弹窗让用户确认**后才写入（不自动照猜）。
- 解析不到先中文词法 → 若用户开启了 LLM 且填好接口，把文本发送给 LLM 辅助解析（**提示数据出本机**）。
- 始终提供手动输入与手动选择日期/重复/优先级作为兜底。

## 9. 架构分层与模块职责
- `core/models`：数据模型 + 序列化
- `core/storage`：JSON 文件访问层（v0.2）；SQLite/Drift 仅作为后续评估项
- `core/sync`：发现、配对、传输、冲突合并
- `core/nlp`：离线中文解析 + LLM client
- `core/notifications`：提醒排程与触发
- `core/rrule`：RRULE 解析/展开（可复用 Dart 的 `rrule` 包）
- `ui/`：收件箱 / 清单 / 看板 / 任务编辑 / 搜索 / 设置 / 同步 / 双语切换

## 10. 风险与待确认项
| # | 风险 / 待办 | 说明 |
|---|---|---|
| R1 | 局域网发现跨平台稳定性 | mDNS 在部分路由器/网络隔离下可能失败 → 保留「输 IP / 扫码」手动兜底 |
| R2 | Windows 常驻被系统杀 | 托盘+开机自启已缓解；不做系统服务（复杂度高） |

| R5 | Flutter Windows 后台能力弱于原生 | 本项目场景（监听局域网同步）够用 |
| R6 | RRULE 中文/边界 | 采用标准 RRULE 库，用例先行验证 |

## 11. 决策记录（ADR 摘要）
- ADR-001：优先 Flutter 单代码库，减少双端维护。
- ADR-002：数据纯本地 + 局域网同步，不引入云（符合用户定位）。
- ADR-003：冲突用任务级 Last-write-wins（简单可预期），字段级 CRDT 留作演进。
- ADR-004：NLP 三级别（离线→LLM→手动），默认离线，数据离机需用户显式授权。
- ADR-005：MIT 协议，开源分发 APK + Windows 安装包。

## 12. 方案自审记录（v1 评审）

> 用途：以"真正要开工实现"的视角复核本方案，记录发现的问题与修订。评审时间：2026-08-19。

### 12.1 发现的关键问题（不合理 / 遗漏）及处理

| # | 问题 | 严重度 | 处理 / 修订 |
|---|---|---|---|
| S1 | **冲突判定只靠系统时钟不稳**：手机/电脑时间不一致会导致 Last-write-wins 判断错误（如手机改了但本机时间落后，被电脑旧改动覆盖）。 | 高 | 数据模型改为 **`version`（单调逻辑计数器 / Lamport 时钟）+ `updatedAt`（墙钟仅作展示）** 共同判定；LWW 以 `(version, updatedAt)` 元组为准。 |
| S2 | **没有增量 / 幂等机制**：直接"全量同步 + 按时戳覆盖"在中断、重连、半写时会丢改或重复。 | 高 | 引入 **outbox/oplog（变更日志）**：每次改动写一条带全局唯一 `changeId` 的日志，同步走"增量交付 + 按 changeId 去重"，天然幂等、支持断点续传。 |
| S3 | **同步方向/握手未定**：架构里"表现频率"与"手机触发"说法混杂。 | 中 | 明确：**Windows 常驻端负责"发现响应 + 提供增量拉取/接收"（Server 角色）；手机端打开 App / 回前台或点了快速同步时发起握手与同步（Client 角色）**。双向都有 heartbeat 保活。 |
| S4 | **回收站与同步语义未定**：删除进回收站后，另一台是否也看到回收站？ | 中 | 决策：删除操作通过 oplog 传播（对方把任务标记为已删除 / 移入"已删除"视图），**回收站仅保留在删除发起端本地**；恢复也只在发起端操作并作为新改动传播。 |
| S5 | **时区 / 夏令时未提**（开放给全球用）。 | 中 | 存储用 **UTC**，本地时区在展示/提醒展开时换算；`dateOnly` 任务不随夏令时漂移。文档补充此约束。 |
| S6 | **提醒对重复系列实例的展开规则未定**（已完成实例是否还提醒 / 提前量落到哪个实例）。 | 中 | 规则：提醒按 RRULE 展开的**下一个未完成实例**排程；实例完成后取消其未触发提醒；全局默认提前量作用于每个实例。 |
| S7 | **"解析结果弹窗确认"的置信度阈值未定义**。 | 中 | 定义：命中强规则直接填但**仍弹确认**（用户要求）；命中弱/模糊规则高亮"未识别部分"，必填项缺失时提示手动补。 |
| S8 | **发布/分发细节缺失**（APK 签名、Windows 安装包、更新、图标命名）。 | 低 | 列入后续「发布计划」：Android APK + 商店可选；Windows 用 Inno Setup 或 MSIX；提供升级说明。 |
| S9 | **多 isolate / UI 不阻塞**未提。 | 低 | 同步、NLP、导入导出在后台 isolate 执行，UI 异步刷新。 |
| S10 | **可测试性**：NLP、RRULE 展开、同步合并必须单测。 | 中 | 三个模块均为纯逻辑、可注入，优先 TDD（见实施计划）。 |

### 12.2 修订后的关键增量
- 数据模型新增字段：`Task.version`（逻辑计数器）、`Task.updatedAt`、`changeId`（oplog）。
- 新增 **oplog（outbox）** 与 **同步引擎**定义：增量、幂等、断点续传、握手/心跳。
- 明确 **Windows=Server 角色、Android=Client 角色** 的同步拓扑。
- 明确 **时区（UTC 存储 + 本地展示）** 与 **dateOnly 不漂移**。
- 明确 **提醒按"下一个未完成实例"排程**。

> 补充说明：若未来需要字段级合并（而非任务级 LWW），可在同步引擎上层引入 CRDT（Yrs / Automerge，参考 AppFlowy），本版选任务级 LWW 以满足当前"简单可预期"的取向。
