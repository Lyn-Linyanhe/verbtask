# 项目调研报告 · 个人任务管理 App

> 日期：2026-08-19
> 目的：为「个人自用 + 开源（MIT）的 Android+Windows 任务管理 App」调研市面现有商业软件与开源项目，吸收经验，反哺 `docs/方案设计.md`。

## 1. 市面主流商业软件调研

| 软件 | 核心卖点 / 功能 | 对我们项目最有价值的点 |
|---|---|---|
| **Todoist** | 自然语言录入业界标杆；复杂重复截止日期；优先级 P1–P4；项目/标签/提醒；跨平台 10+ 端 | **NLP 实时解析 + 预览确认**（输入时就看到识别出的日期/优先级）；重复任务写法约定（"every 2 days" 而非 "every other day"；日期放句尾识别更稳）。 |
| **滴答清单 TickTick** | 提醒、番茄钟、日历视图、重复任务、习惯打卡、内置日历 | 提醒与日历集成；多维度提醒体验。 |
| **Microsoft To Do** | "我的一天(My Day)"、智能清单、跨设备同步 | 简洁"今日聚焦"理念；清单组织。 |
| **Things 3** | 项目/区域/标签、截止日、Markdown 备注、极致设计、键盘快捷键 | **设计即卖点**：美观、动画、键盘效率；Area/项目体系成熟。 |
| **Any.do** | 简洁、提醒、日历聚合 | 极简快速录入。 |
| **Google Tasks** | 简洁、与 Gmail/日历/Assistant 集成、子任务 | 深生态绑定；子任务。 |

**共性与结论（商业软件）**：
- 自然语言录入是评价分水岭（Todoist 最强），且普遍采用"**解析后可预览/确认**"。
- 都支持 重复任务、优先级、截止日期、提醒 作为基础四件套。
- 组织方式主流是"清单/项目 + 标签 + (可选)区域/文件夹"。
- 多为**云端账号 + 跨设备实时同步**（这与我们"纯本地 + 局域网同步"不同，见 §3 取舍）。

## 2. 开源项目调研

| 项目 | 定位 | 技术栈 / 数据 | 同步方式 | 许可证 | 可借鉴点 |
|---|---|---|---|---|---|
| **Taskwarrior** | CLI GTD 任务管理 | C++ / 本地文本+SQLite 存储 | 可选 Taskchampion 同步（云端/自托管）；本地为主 | MIT | 本地优先、可脚本化；`recur:` `due:` `project:` 自然标注；纯本地也能很强大。 |
| **Todo.txt** | 纯文本待办 | 纯文本文件 + 脚本 | **无内建同步**（手动 Git/网盘/Dropbox） | MIT | 数据即文件、可版本化；**导入/导出是本地应用的生命线**。 |
| **Vikunja** | 自托管任务/项目（对标 Todoist/ClickUp） | Go 服务端 + 网页/桌面/移动客户端 | **服务端为真相源**，自托管 | AGPL | 看板+清单+子任务+协作；但需服务器（非我们的定位）。 |
| **Joplin** | 笔记+待办勾选 | Electron + SQLite，客户端本地优先 | Joplin Cloud / WebDAV / Nextcloud / Dropbox / OneDrive / 本地文件 | AGPL（核心） | **"本地优先 + 用户自选同步目标"**的标杆：不绑定厂商、隐私友好。 |
| **AppFlowy**（Notion 开源替代） | 文档+表格/看板+AI | **Flutter 前端 + Rust 后端 + SQLite**，本地优先 + 可选云 | 可选 AppFlowy Cloud；文档用 **CRDT(Yrs)** | AGPL | **验证了 Flutter 做本地优先双端**；客户端优先架构；需要协作用 CRDT。 |
| **Super Productivity** | 任务+时间追踪 | Web + 桌面 + 移动 | WebDAV / Nextcloud / Dropbox，**无中心服务器** | MIT | 多端同步可不依赖自建服务器。 |
| **Tasks.org**（Astrid 继任） | Android 本地任务 App | Android 原生 | 可选 Google Tasks / **CalDAV** / **EteSync**(E2E)；完全离线可用 | GPL-3.0 | **"完全离线 + 用户可选同步后端 + 无追踪 + 导入导出"**的隐私范本；子任务/重复/位置提醒/自定义筛选。 |

**关键启示（开源项目）**：
1. **本地优先是成熟且受认可的方向**：Joplin / Tasks.org / Super Productivity / Taskwarrior 都证明"数据留本机、同步可选"可行且广受隐私用户欢迎。
2. **同步要么"自选云/WebDAV/CalDAV"，要么"自托管服务器"**：这两类都离开设备；我们选**局域网（LAN）同步**是更"纯"、但能力更受限的一档——需要靠健壮的**增量/幂等/冲突处理**补足（对应方案自审 S1/S2）。
3. **架构参考**：AppFlowy 的 Flutter+SQLite 本地优先被验证；但我们做的是轻量任务 App，**可保持纯 Dart（不需要 Rust/FFI**），降低复杂度。
4. **协议/许可**：Taskwarrior/Todo.txt/Super Productivity 用 MIT（宽松）；Joplin/Vikunja/Tasks.org 用 AGPL/GPL（强制开源、防闭源分发）。我们选 **MIT** 最利于别人自由复用什么场景都行；若日后想阻止闭源再考虑 AGPL。
5. **工程素质**：Todo.txt 的"数据可版本化/可导出"、Taskwarrior 的"可脚本化/可测"，都指向**干净的数据模型 + 优先做导入导出 + 单测核心逻辑**。

## 3. 与我们定位的取舍对比

| 维度 | 商业主流（Todoist 等） | 开源主流（Joplin/Tasks.org 等） | **我们的选择** |
|---|---|---|---|
| 数据 | 云端账号 | 本地优先，可选手动/第三方同步 | 纯本地 + **局域网同步** |
| 实时跨设备 | 随时随地 | 视同步源而定 | 仅回家同 Wi‑Fi 时（已确认接受） |
| 账号 | 必须注册 | 无（或可选 EteSync 等） | **无账号** |
| 自然语言 | 强（Todoist） | 弱/无 | 自建：**离线中文 + 可选 LLM + 手动** |
| 开源 | 闭源 | MIT/GPL/AGPL | **MIT** |

> 结论：我们在"同步实时性"上主动放弃云端便利，换取"无账号、纯本地、隐私可控、零运维"。这正好对标 Joplin/Taskwarrior/Todo.txt 一批"极客向本地优先"应用的口碑，但我们需要用**扎实的增量同步与冲突处理**（而不只是"网盘文件夹"）来保证可靠。

## 4. 对方案的具体改进建议（已吸收）

1. **NLP 采用"实时解析 + 弹窗确认"**（吸收 Todoist 预览 + 我们的确认要求）。
2. **把导入/导出、回收站列为一等公民**（吸收 Todo.txt/Tasks.org：本地应用数据可带走、可恢复）。
3. **冲突处理用 逻辑版本(version) + oplog 增量 + 幂等**（吸收 Vikunja/Taskwarrior 对同步一致性的重视 + 方案自审 S1/S2）。
4. **架构保持 Flutter + 纯 Dart 本地优先**：AppFlowy 验证了 Flutter 跨 Android/桌面的可行性；VerbTask v0.2 保持 JSON 文件仓库以降低迁移风险，SQLite/Drift 只作为数据量和查询需求增长后的评估项，不在当前版本强行引入。
5. **提供可选扩展点**：未来若想"随时随地同步"，方向是给用户自选 WebDAV/CalDAV（Joplin/Tasks.org 模式），代码上预留同步抽象层即可。
6. **许可**：维持 MIT，文档注明"如需防止闭源再议 AGPL"。

## 6. UI / 交互深挖（2026-08-20）

本节只记录能够从官方产品页、帮助文档或公开产品截图核对的界面结构，不把营销页未展示的细节当成事实。

### 6.1 信息架构

| 产品 | 可核对的核心入口 | 对 VerbTask 的启示 |
|---|---|---|
| Todoist | Inbox、Today、Upcoming、项目、过滤器，并在列表/日历/看板间切换 | 用 `Inbox -> Today -> Planned` 覆盖收集、执行、规划；复杂筛选先隐藏在工具入口 |
| Things 3 | Inbox、Today、Upcoming、Anytime、Someday；官方指南明确各自用途 | “现在做什么”和“以后再安排”应分开，减少把所有任务堆在一个列表里的压力 |
| Microsoft To Do | My Day + 用户自建清单；公开截图显示低密度列表 | 今日视图保持安静，任务行不长期展示所有字段 |
| Any.do | Daily Planner、任务与日历概览、Android 小组件 | 移动端要支持快速回看和稍后安排；小组件列为后续增强，不阻塞核心页面 |
| TickTick | 清单、日历、习惯、专注、统计等多个模块；Date & Repeat 集中管理日期和重复 | 日期、重复、提醒集中在详情页；不复制习惯/番茄钟/统计造成的首版噪音 |

**规划决策：** VerbTask v0.2 保留 `收件箱 / 今天 / 计划 / 清单 / 已完成 / 看板` 六种视图。首页仍以收件箱作为默认入口，因为它直接承接用户已经确定的“随手记录”流程；“今天”作为同级的一键执行视图，而不是把无截止日期的新任务隐藏起来。Windows 宽屏再增强侧栏，Android 保持单列低密度列表。

### 6.2 任务行与详情

公开截图和官方功能说明共同呈现出一个稳定模式：任务行只保留完成操作、标题和少量日期/重复/提醒摘要；备注、清单、优先级、RRULE 等复杂字段进入任务详情。这样既保留快速扫描，也避免每行变成表单。

**规划决策：** VerbTask 任务行采用“状态点 + 完成圆钮 + 标题 + 截止摘要 + 重复/提醒图标”结构。点击行进入详情，完成圆钮只负责完成/恢复。看板复用同一任务行，不为看板另造一套字段语义。

### 6.3 快速录入与解析反馈

- Todoist、TickTick 都把自然语言日期/重复作为快速捕获的重要能力。
- TickTick 官方帮助把日期和重复放在 `Date & Repeat` 入口；Todoist 的公开帮助示例展示了 `every Monday`、`monthly` 等写法。
- 产品宣传可以做到“输入即解析”，但对本项目更重要的是解析结果可见、可修正、可取消。

**规划决策：** 快速录入框与搜索框必须分离。提交自然语言后统一弹出确认面板，显示标题、截止模式（仅日期/日期+时刻）、重复、清单、提醒和未识别片段；确认前不写入。搜索只改变查询结果，绝不触发 NLP 弹窗。

### 6.4 本地优先产品的界面边界

Tasks.org、Joplin、Super Productivity、Taskwarrior/Todo.txt 的共同价值不在于界面装饰，而在于“离线可用、数据可带走、同步是可选边界”。Vikunja 的看板和项目层级适合协作/自托管场景，但会把个人 App 推向服务端产品。

**规划决策（按路线图分阶段实现）：** 设置页应明确展示本地数据、备份/导入导出、LLM 数据外发开关；局域网同步状态和配对信息属于 v0.3 同步阶段，不假设已在 v0.2 页面存在。不引入账号、团队成员、云端必选步骤。回收站、JSON 备份和 CSV 导出是发布基线，不作为视觉上的次要功能。

### 6.5 竞品借鉴审查

| 结论 | 审查结果 | 处理 |
|---|---|---|
| 直接复制 Todoist/TickTick 的全部模块 | 不符合个人、无账号、低噪音定位 | 只吸收 NLP、Date & Repeat 和少量视图 |
| 采用 Things 3 的 Areas/Projects/Tags 全层级 | 超出用户已确认的“清单 + 收件箱”组织方式 | v0.2 只做清单；标签/文件夹不加入核心 |
| 默认进入 Today | 有助于执行，但会隐藏没有截止日期的新收集项 | 保留收件箱默认，Today 同级突出；日后可做用户可选默认视图 |
| 以云端账号换实时同步 | 与纯本地无账号约束冲突 | v0.3 实现 Windows 监听节点 + Android 手动/前台触发的 LAN 同步 |
| 用 SQLite 替换现有 JSON | 当前收益不足且会扩大迁移风险 | v0.2 保持 JSON，先把查询、原子写、备份和测试做好 |
