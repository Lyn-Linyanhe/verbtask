# VerbTask v0.2 日常工作流设计

> 状态：2026-08-20 评审版
> 依据：`docs/方案设计.md`、`docs/项目调研报告.md`、2026-08-20 竞品调研、当前仓库代码核验

## 1. 目标

把当前“能运行的功能原型”推进为可日常使用的个人任务工具：用户可以快速收集任务、整理到清单、按今天/计划查看、搜索筛选、完整编辑任务、接收可靠提醒，并在中英文界面间切换。

本阶段保留现有 Flutter + JSON 文件仓库，不迁移 SQLite，不重写状态管理，不扩展云同步。这样可以利用现有可运行代码，把竞品验证过的核心工作流先做完整。

## 2. 当前基线与审查结论

- 已有：Task 模型、任务 CRUD、软删除、JSON 持久化、基础中文解析、RRULE、LLM 客户端、通知排程原型、LAN 发现/HTTP 同步原型、Windows 托盘原型。
- 缺失：清单 CRUD、完整任务编辑、首页搜索/排序/筛选、真正的三列看板、LLM 录入接线、完整中英双语、提醒默认值和旧排程清理、通知权限引导。
- 高风险但不在本阶段：LAN 同步没有配对/认证/增量游标/幂等去重，任务列表也没有同步。它们进入 v0.3 可靠同步专项，v0.2 不把当前同步原型宣传为安全同步。
- 原方案中的 SQLite/Drift、Riverpod/Bloc 和 Oplog 表没有对应当前代码。本阶段以当前 JSON 实现为事实基线，并通过原子写入、格式版本校验和唯一变更 ID补足短期可靠性。

## 3. 用户工作流

### 3.1 快速收集

首页输入框只负责快速收集。提交后执行本地中文解析；LLM 开关开启且配置完整时，先尝试 LLM，失败自动回退本地解析。无论来源是什么，都显示统一的解析确认弹窗，确认前不写库。

确认弹窗至少展示：标题、截止日期（仅日期/具体时刻）、重复规则、优先级、目标清单和提醒状态。解析不到的字段显示“未设置”，用户仍可以确认创建或进入完整编辑。

### 3.2 整理与执行

移动端默认采用低噪声单列列表，借鉴 Things 3 和 Microsoft To Do：

- 收件箱：`listId == null` 的未整理任务。
- 今天：截止日期落在本地今天的任务，以及逾期任务。
- 计划：所有有截止日期的未完成任务，按截止时间排序。
- 清单：按实际清单查看任务，支持新增、重命名、删除。
- 已完成：已完成任务聚合视图。
- 看板：按未开始、进行中、已完成三列查看；手机上以可横向滚动列展示，Windows 上允许更宽的列。

任务行只有一个主操作：完成/恢复。标题、截止时间、重复图标和状态点是辅助信息；点击任务进入详情。

### 3.3 完整编辑

详情页支持：标题、备注、状态、清单、截止日期、仅日期开关、提醒、重复规则和弱化的优先级选择。保存沿用现有 `TaskService.edit`，不在 UI 层直接写仓库。

本阶段重复规则编辑采取“编辑当前任务系列”的默认语义；“只改这一次/这一次及以后”需要实例化模型，列入 v0.3 重复任务专项，不在 v0.2 伪造未实现的行为。

## 4. 数据与兼容性

### 4.1 JSON 存储

- 保持当前 `{version, tasks, lists, changes}` 文件格式；新增字段必须带默认值，旧数据可以读取。
- 写入采用同目录临时文件 + flush/rename 的原子替换路径；解析失败时保留坏文件并从空仓库启动，不能静默覆盖原始数据。
- `Task.changeId` 由 UUID 生成；`TaskList` 在 v0.2 只承担本地 CRUD，保留 `updatedAt`，同步元数据在 v0.3 补齐。
- `dateOnly` 继续作为显式字段；展示使用本地时区，序列化使用 UTC。v0.2 补充跨时区测试，但不改变已有 JSON 字段名。

### 4.2 业务边界

`TaskService` 负责任务和清单的业务操作；`FileRepository` 负责文件读写；页面只依赖 service 和 controller。删除清单时，清单内任务移动到收件箱，再物理移除清单，避免悬空 `listId`。

## 5. 提醒规则

- 任务有单条提醒时只使用单条提醒。
- 任务没有单条提醒但有截止日期时，只有在全局默认提醒开关开启时才使用默认提前量。设置由 `notifyDefaultReminderEnabled`（布尔值）和 `notifyDefaultOffsetMin`（有符号整数）组成：负数表示提前，`0` 表示到期时刻；默认开启、默认偏移为 `-30`。关闭不能用 `0` 表示，而是由独立开关表达。
- 排程服务接口的 `defaultOffsetMinutes` 使用可空整数：`null` 表示关闭全局默认提醒，非空值沿用上述有符号偏移语义。
- 每次全量重排前先取消由 VerbTask 创建的旧提醒，再排当前未删除、未完成任务。
- 重复任务以 `due.value` 作为 RRULE 起点；没有截止日期的重复任务不排通知。
- 修改、完成、恢复、删除和导入后都触发重排。
- Android 运行时权限状态在设置页可见；权限被拒绝时显示可执行的系统设置入口，但不阻塞任务保存。

## 6. 本地化与 UI

- 所有用户可见文本迁移到 `app_zh.arb` / `app_en.arb`，包括页面标题、按钮、空状态、解析预览、提醒状态和错误提示。
- 不引入新的 UI 状态管理框架；沿用当前 `StatefulWidget`、`SettingsController` 和 `TaskService`。
- 主题保留已完成的冷灰白底 + 靛蓝强调色；任务工作区不增加营销式大卡片。
- Windows 宽屏优化留到 v0.3；v0.2 保证同一套移动优先布局在 Windows 可用。
- `LlmDraft` 必须携带可选 `dateOnly`，解析结果不能因 LLM 来源而丢失“仅日期/日期+时刻”语义；缺失时默认 `false`。

## 7. 错误处理

- LLM 网络失败、响应格式错误或超时：提示“已回退到本地解析”，仍显示确认弹窗。
- 备份格式错误：显示具体格式错误，不改动已有数据。
- 通知权限缺失：保存成功，设置页提供权限引导。
- 清单删除：明确提示任务将移入收件箱。
- 查询、导入、同步异常：保留当前页面数据，显示可关闭的错误提示，不让异步异常击穿页面。

## 8. 验收标准

- 可创建、编辑、删除、恢复任务；完整编辑页能修改本阶段列出的所有字段。
- 可创建、重命名、删除清单，清单删除不会留下悬空任务。
- 首页可在收件箱、今天、计划、清单、已完成和看板之间切换；搜索、状态/清单筛选和截止排序可组合使用。
- 中文快速录入、本地解析、可选 LLM、确认弹窗和手动兜底均可走通。
- 有截止日期的任务按默认提醒规则排程；重排不会残留旧提醒。
- 中英文切换后，首页、编辑页、设置页、回收站和解析弹窗没有中文硬编码泄漏。
- JSON 旧数据可读取，写入失败不会覆盖原文件。
- `flutter analyze`、完整 `flutter test`、Android debug 构建和 Windows 构建通过。
